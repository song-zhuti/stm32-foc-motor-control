# 1 项目概述

项目名称：

STM32 BLDC 控制实验项目

项目目标：

基于以下硬件建立一个可持续扩展的 BLDC 控制实验平台：

- MCU：STM32F103C8
- Driver Board：SimpleFOCmini
- Driver Chip：MS8313
- Motor：BLDC
- Encoder：AS5600

当前阶段目标：

- 建立稳定的嵌入式工程结构
- 完成 ADC + DMA 采样架构
- 完成编码器角度读取
- 将电机驱动从 GPIO 升级为 PWM
- 为后续 FOC 控制做准备

项目性质：

学习型嵌入式开发项目。

## 规则 9

控制系统开发规则。

本项目属于嵌入式控制系统工程（电机控制 / FOC 算法），代码结构必须保持清晰的控制链路。

基本原则：

1. 控制算法模块与外设驱动模块必须分离。

- 外设驱动放在 Hardware 模块
- 控制算法放在 foc 模块
- 主循环只做调度与调试输出

2. 中断函数中只允许执行轻量逻辑。

中断中允许：

- 更新标志
- 记录节拍
- 简单数据处理

中断中不允许：

- 执行复杂控制算法
- 执行长时间计算
- 执行 OLED / 串口等慢速外设操作

3. 控制周期必须由定时器统一调度。

控制任务应由定时器产生节拍，例如：

TIM3 中断
-> 控制任务触发
-> 控制算法执行

避免使用：

- while 循环延时
- 不确定周期的任务触发

4. 数据采样链路与控制链路必须解耦。

推荐结构：

ADC采样
-> DMA传输
-> 数据滤波
-> 反馈量计算
-> 控制算法
-> PWM输出

采样逻辑不应直接依赖主循环。

5. 控制模块应保持最小接口原则。

控制模块应提供：

- 初始化接口
- 控制任务接口
- 参数设置接口

不应暴露内部状态变量。

6. 调试输出必须低频执行。

OLED / 串口输出只允许在主循环或低频任务中执行，避免影响控制周期稳定性。

7. 新功能开发应遵循最小侵入原则。

新增模块时：

- 不破坏现有采样链路
- 不修改已稳定的外设驱动
- 优先通过新增接口扩展功能

## 规则 10

AI 在参与本项目开发时，需要遵循 渐进式知识讲解原则。

本项目属于 学习型嵌入式开发项目，开发者在实现功能的同时逐步学习相关技术，因此 AI 在解释知识时应控制信息密度。

基本原则

AI 不要一次性讲解过多扩展知识，应优先保证当前任务能够完成。

优先顺序应为：

1 当前问题解决
2 当前功能实现
3 当前代码能够运行与验证
4 再补充相关原理与扩展知识

知识讲解节奏

当开发者正在解决一个具体工程问题时，例如：

PWM 初始化

ADC + DMA 配置

Encoder 读取

控制任务调度

AI应优先：

解释 完成当前任务必须理解的知识

指出 实现步骤

提供 验证方法

不应在此阶段展开：

大量原理推导

未来阶段的复杂架构

与当前任务无直接关系的扩展内容

扩展知识讲解时机

AI 可以在以下时机补充扩展知识：

1 当前功能 已经成功运行

例如：

PWM 已经成功输出

ADC 采样链路稳定

Encoder 数据读取正常

2 开发者主动提出学习需求

例如：

想理解某个寄存器

想理解某个控制原理

想深入学习某个模块

3 当前知识 在下一阶段开发中将直接使用

例如：

在 PWM 完成后讲解 MOE / Preload

在 Encoder 稳定后讲解角度连续化

在闭环控制前讲解控制周期结构

AI教学方式建议

AI解释知识时应优先采用：

工程结构视角

模块职责视角

控制链路视角

避免：

过度理论化解释

与当前工程无关的知识扩展

一次性讲解完整知识体系

示例（本项目案例）

例如：

当开发者正在实现 TIM1 PWM 输出 时：

AI应优先帮助完成：

GPIO PWM 复用配置

TIM1 PWM 初始化

CCR 占空比控制

PWM 成功输出验证

而以下内容应 延后讲解：

MOE 主输出控制

CCR Preload

互补 PWM

死区时间

电机驱动保护机制

当 PWM 成功输出后，再逐步补充这些知识。

目标

该规则的目标是：

保持开发节奏稳定

保证学习内容与当前工程进度同步

避免信息过载

提高工程实践效率

## 规则 11

AI 在解释技术知识时，应 优先结合当前项目代码进行讲解。

解释应尽量基于：

当前工程中的模块

当前代码中的函数

当前工程中的外设配置

当前项目的控制链路

例如：

解释 PWM 时优先结合当前工程的 TIM1 初始化代码

解释 ADC 时优先结合当前工程的 ADC + DMA 配置

解释控制调度时优先结合当前工程的 TIM3 调度结构

避免：

只给出抽象理论说明

给出与当前项目无关的示例代码

讲解与当前工程结构不一致的实现方式

目标

该规则的目标是：

提高知识解释的工程相关性

减少抽象理论学习带来的理解负担

让学习过程与实际项目开发同步推进

## 规则 12

AI 在参与开发协作时，应主动协助维护项目文档。

当出现以下情况时，AI应主动提醒开发者更新开发记录：

- 当前开发任务阶段基本完成
- 当前功能已经验证通过
- 当前讨论已经形成稳定结论
- 对话进入总结或收尾阶段
- AI判断开发者可能准备结束当前开发会话

在这些情况下，AI应主动提出：

- 是否需要更新 `Docs/Notes/Plain next.md`
- 今天的开发记录应写入哪些内容
- 是否有新的 TODO 需要记录
- 是否有新的规则需要更新到 `ai_context.md`

AI可以根据当前对话内容，整理建议的文档更新内容，例如：

- 今日完成任务
- 今日学习的关键知识
- 当前系统状态
- 下一步开发计划

开发者确认后再写入文档。

该规则的目标是：

- 保证开发记录持续更新
- 避免遗漏重要的学习与设计决策
- 让项目文档始终与开发进度同步
